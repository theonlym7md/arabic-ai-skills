# اختيار تصميم الصفحة بحسب المهمة

اقرأ هذا المرجع عند تصميم شاشة أو مسار كامل، أو عند مراجعة بنية واجهة قائمة. ابدأ من المحتوى الفعلي وهوية المشروع الحالية والجهاز الأهم للمهمة. هذا مرجع مستقل داخل `arabic-uiux-master` ولا يتطلب تثبيت المهارة الرئيسية.

## من الطلب إلى أول تصميم

1. حدّد ما يريد المستخدم فعله الآن، وما يحتاج إلى معرفته قبل الالتزام، وما يجب أن يبقى معه إذا رجع أو انتقل إلى تطبيق آخر.
2. قارن بين بنيتين قابلتين للتنفيذ على الأقل عندما يترك الطلب البنية مفتوحة. قيّم وضوح أول إجراء، وعدد القرارات، وكلفة الخطأ، ومدى ملاءمة البنية للمحتوى والجوال. إذا طلب المستخدم واجهة واحدة فابنِ الخيار الأنسب. إذا طلب بدائل فاعرض خيارين أو ثلاثة مع أثر كل خيار وسبب ترجيحك.
3. حدّد ترتيب المحتوى قبل الألوان. عيّن عنصرًا بصريًا رئيسيًا يشرح الفكرة، مثل صورة وجهة للتخطيط، أو لقطة منتج لإثبات الفائدة، أو جدول يوضح فرق السعر. اشتق الألوان والخطوط وكثافة الصفحة من هوية المنتج واحتياجه إلى القراءة أو المقارنة. عند وجود نظام تصميم اعمل ضمنه.
4. صمّم أصعب حالة متوقعة بجانب الحالة العادية. اربط عنوانها وزرّها بالإجراء المتاح فعلًا. تحقّق من ترتيب القراءة والتركيز في RTL وعلى الجوال، ومن طول العنوان الحقيقي والتفافه، ومساحة السعر والنصوص المختلطة، وتباين الحدود والنصوص.

## بدائل تركيب الصفحة

| مهمة المستخدم | بديلان مناسبان | كيف تحسم الاختيار |
| --- | --- | --- |
| فهم عرض جديد | افتتاحية تحريرية بصورة وقصة قصيرة، أو شرح مصوّر للمنتج مع مهمة واضحة | استخدم القصة عندما يحتاج المستخدم إلى تكوين صورة عن التجربة. قدّم شرح المنتج أولًا عندما يبحث عن وظيفة بعينها ويريد رؤية طريقة عملها. ضع الإثبات قرب الادعاء الذي يدعمه. |
| العثور على شيء معروف أو اكتشاف الخيارات | بحث بارز مع مرشّحات، أو تصفّح موجّه حسب النية مع مجموعات منتقاة | قدّم البحث عند وجود اسم أو مكان أو رقم يعرفه المستخدم. استخدم المجموعات عند غياب مصطلح بحث مألوف. إذا كانت الوجهة تغيّر التوفر فاطلب المدينة في اللحظة التي تؤثر فيها وأبقِ الاختيار قابلًا للتعديل. |
| تقييم عنصر أو خدمة | تفاصيل سريعة بجوار الإجراء، أو صفحة متعددة المقاطع تبدأ بملخص قابل للمسح | استخدم التفاصيل المجاورة إذا حسم القرار سعر أو موعد أو شرط واحد. استخدم مقاطع واضحة إذا احتاج القرار إلى شروط ومقارنة وأمثلة. كرّر السياق الضروري عند أسفل صفحة طويلة قبل زر الالتزام. |
| إيجاد مكان مناسب | قائمة تقارن العناصر، أو خريطة متزامنة مع القائمة | اجعل القائمة أساسية إذا كانت الأسعار أو الخصائص هي معيار المقارنة. ابدأ بالخريطة إذا كانت المسافة أو المنطقة هي السؤال الأساسي، وأبقِ قائمة مكافئة لاستخدام لوحة المفاتيح وقراءة التفاصيل. |
| إتمام مهمة متكررة | مساحة عمل تبدأ بالإجراء أو البيانات الحالية، أو صفحة توجيه توضّح الخطوة التالية | ابدأ بالعمل لمن يعرف المهمة وتكثر زياراته. أضف توجيهًا عندما تختلف وجهة المستخدم باختلاف الإذن أو الدور أو حالة الطلب. |
| فهم مكتبة محتوى | فهرس بحسب الموضوع أو الصيغة، أو قصص منتقاة تقود إلى الأرشيف | استخدم الفهرس للاسترجاع المتكرر، والقصص حين تكون الأولوية لتقديم أعمال أو أصوات جديدة. اذكر المدة أو الموسم أو اللغة حين تؤثر في الاختيار. |
| إكمال طلب | استمارة قصيرة في صفحة واحدة، أو خطوات تحفظ البيانات وتعرض المسار | اجمع الحقول إذا كانت قليلة ومعروفة. قسّمها إذا تغيّرت المتطلبات بحسب الإجابة أو احتاج المستخدم إلى مرجع أو وقت قبل الإرسال. أظهر إمكانية المراجعة وميّز بين حفظ المسودة وإرسال الطلب. |

## هوية وتكوين يناسبان الفكرة

- حدّد ما يجب أن يلاحظه المستخدم أولًا وما يحتاج أن يجد بسهولة في الزيارة التالية. اكتب عنوانًا يوضح الأول، واجعل التنقل أو الأدوات تحمل الثاني.
- غيّر التكوين عندما تتغيّر المهمة. يمكن لتطبيق ثقافي أن يبدأ بمحرك بحث عند بيع التذاكر، وبقصة وصور عند تقديم معرض. يمكن لمتجر وعيادة استخدام محدد موقع واحد وظيفيًا، مع اختلاف المحتوى واللغة ومقدار التفاصيل.
- اجعل الصور ذات غرض واضح، واختر المقاسات والقص على الجوال مع بقاء العنصر الذي يشرح المحتوى.
- ابدأ بفصحى مرنة عند غياب صوت معتمد، والتزم خصائص CSS المنطقية والطباعة العربية (`letter-spacing: 0`)، ثم اطّلع على [أنماط التصميم وتدفقات الواجهة](flow-patterns.md) عند الدخول أو الدفع أو الحجز.
