# سلامة التوطين

## ملفات الترجمة

- احفظ مفاتيح JSON والمتغيرات مثل `{name}` و`{{amount}}` و`%1$s` حرفيًا، وبالعدد نفسه لكل رسالة.
- لا تترجم وسوم HTML أو عناوين URL أو أسماء المتغيرات؛ ترجم النص الظاهر فقط.
- حافظ على الترميز وبنية JSON/ICU، ولا تضع تعليقات أو أسوار Markdown إذا طُلب JSON فقط.
- في ICU يمكن إضافة فئات الجمع المطلوبة للعربية، مع حفظ اسم وسيطة الجمع والمتغيرات داخل الفروع ومعناها؛ لا تفرض تساوي عدد المتغيرات على الملف كاملًا بعد إضافة فروع جديدة.
- إذا كانت الصيغة غير معروفة اسأل عن المحرك قبل اختراع بناء خاص به.

## الجمع والجنس

العربية ليست صيغة مفرد وصيغة جمع فقط. استخدم فئات CLDR التي يدعمها المحرك:
`zero`, `one`, `two`, `few`, `many`, `other`.
اختبر 0 و1 و2 و3 و11 و100 وقيمة عشرية. لا تستخدم `count === 1`
قاعدةً مكتملة للعربية. القواعد النحوية للاسم والسياق تحتاج مراجعة أيضًا.
لا تستنتج جنس الشخص من اسمه؛ فضّل صياغة محايدة عند غياب معلومة موثوقة.

## الأرقام والمحتوى ثنائي الاتجاه

احفظ قيمة المبلغ والعملة والمعرّف كما وردت. نسّق حسب locale المطلوب دون
تحويل عملة أو تقويم من تلقاء نفسك. لا تعكس أرقام الهاتف أو رمز التحقق.
في HTML اعزل القيمة الديناميكية بـ `bdi`، واضبط الاتجاه للمعرّفات المعروفة.
فضّل بيانات الاتجاه في الواجهة على إدخال محارف خفية في النص القابل للنسخ.
إذا كان النص الصرف يتطلب محارف عزل، وضّحها بصيغة Unicode مهروبة واختبر النسخ.

## حدود الطول

اسأل هل الحد كلمات أم محارف إذا كان ذلك يغيّر النتيجة.
احسب بالطريقة المحددة؛ عدد الكلمات أو المحارف لا يثبت أن النص يلائم زرًا
بعرض محدد. حافظ على معلومات القرار ولو استلزم ذلك بيان تعارض القيود.

مراجع: [Unicode CLDR](https://cldr.unicode.org/index/cldr-spec/plural-rules)،
[W3C: عزل الاتجاه](https://www.w3.org/International/questions/qa-bidi-unicode-controls).
