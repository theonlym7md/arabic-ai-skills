# تجربة مقارنة ArabicSkill

تُظهر التجربة مخرجات كتابة الواجهة، لا جودة تصميمين مختلفين. استخدمنا نفس نموذج Codex الموروث من الجلسة في تشغيلين مستقلين بسياق محادثة فارغ، مع [طلب واحد وحقائق ثابتة](brief.md). لم نثبّت رقم لقطة النموذج أو بذرة التوليد، لذلك لا يُتوقع أن يعيد تشغيل جديد النص نفسه حرفيًا.

- **بدون مهارة:** توليد بالنموذج وحده، دون قراءة أي مهارة أو مراجع أو ناتج الشرط الآخر.
- **مع المهارة:** استخدم التوليد [ArabicSkill v2.2.0](https://github.com/theonlym7md/arabic-ai-skills/tree/v2.2.0/skills/arabicskill) فقط، دون المهارة المرافقة أو مراجع خارجية. تحققنا أن العلامة وأحدث فرع منشور وقت التجربة يشيران إلى الالتزام `819c010e08efe21c1170d32a66100fbab946434b`.

نقلنا النصوص كما وردت إلى [ملف المخرجات](copy.js)، دون تنقيح أي شرط. جرى العرض بعد التوليد بقالب HTML/CSS واحد لكل زوج، مع حقول ثابتة مشتركة من الطلب (قيمة التذكرة والبريد التجريبي). الاختلاف البصري داخل كل زوج ينتج من النص وطوله، وليس من تبديل الألوان أو الخطوط أو ترتيب القالب.

## عرض اللقطات وإعادة التقاطها

افتح [صفحة العرض](index.html) من النسخة المحلية في متصفح، أو شاهد الصور مباشرة: [الهبوط](../../assets/ab/landing.png) · [الدفع](../../assets/ab/payment.png) · [تسجيل الدخول](../../assets/ab/login.png).

لإعادة الالتقاط، استخدم Node.js مع Playwright وChromium متاحين محليًا، ثم شغّل من جذر المشروع:

```sh
node docs/demos/arabicskill-ab/capture.cjs
```

يمكن ضبط `DEMO_BROWSER_PATH` لاستخدام Chrome مثبت بدل Chromium المرفق. التقطنا الشاشات من نافذة بعرض ١٤٤٠ بكسل، وتحققنا من تساوي أبعاد الشاشتين في كل زوج، ومن عرض النص كما هو، ومن تكديس النسختين على عرض ٣٧٥ بكسل دون تمرير أفقي. لا تُرسل الواجهات أي بيانات، ولا تحتاج إلى خدمة خارجية.
